# Latency measurement definitions

No experiment subtracts historical/simulated event time from a current processing
clock. Acoustic `wall` timestamps describe stream position and controlled source
start, not necessarily actual publication time. The injected control event is an
event-time finalization device in the isolated topic, never a transport sample.

| Boundary | Instrumentation | Interpretation |
| --- | --- | --- |
| Acoustic event creation → enqueue | Not separately instrumented | No value claimed; queued acoustic messages were generated by actual finite simulation |
| Producer enqueue → Kafka acknowledgement | `time.monotonic()` at accepted queue insertion after validation, same-process callback monotonic clock | Includes application queue, worker and broker acknowledgement; excludes event construction/validation |
| Kafka availability → individual Spark processing | Not correlated per record | No percentile claimed; Spark reports aggregate batch input/processed rates and execution duration |
| Spark processing → committed Parquet visibility | Native sink progress after batch, separately timed verification | No independently isolated per-record duration; inclusive job and verification wall durations retained |
| Export/Parquet → API availability | Separate offline export then owned API server startup to first successful real request | One orchestration observation, includes server startup; not a distributed transport percentile |
| API request → response | 20 sequential same-host HTTP requests after one warmup | Valid local HTTP p50/p95/p99 over that population, not a load test |
| API response received → corresponding dashboard row visible | Same Node `performance.now()` clock in the Chromium test | One observed browser/React/automation interval; no percentile from a single sample |

Producer sample rings are bounded to 4,096 observations. The 100-events/s workload
has 6,000 measured-phase records, so its retained latency population is explicitly
only the last 4,096 measured acknowledgements. The 1,500-record warmup is drained
and excluded before the measured phase starts. Failed acknowledgements do not
enter successful latency percentiles; their counts remain in producer metrics.

The host and Docker containers share the same host wall clock, but no subtracted
wall timestamps are used to infer a network delay. Telemetry heartbeat/progress
ages use timezone-aware UTC and are freshness indicators, not end-to-end transport
latencies. Spark event-time watermark lag remains distinct. Local experiments
cannot establish cross-machine clock synchronization or network performance.
